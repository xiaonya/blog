复习测试 · Day 3-4（Namespace + Label）

日期：2026-08-25 满分：60 分 对应笔记：week2-day3-Namespace.md + annotation 实操

一、判断题（每题 2 分，共 10 分）​

  1. （ ）Namespace 可以嵌套，dev 下面可以再建 dev/frontend 子命名空间。

  2. （ ）kubectl delete namespace dev 会删除 dev 下的所有 Pod、Service，但不会删除其中的 ConfigMap。

  3. （ ）kubectl get pods -l env!=prod --all-namespaces 会返回所有没有 env 标签的 Pod。

  4. （ ）Annotation 和 Label 一样，都可以用 --selector 来筛选资源。

  5. （ ）Node、PV、StorageClass 这类集群级别资源不受 Namespace 约束，任何 namespace 的用户都能看到（取决于 RBAC 权限）。

二、填空题（每空 2 分，共 20 分）​

  1. 删除一个 Pod 上的 label env，命令是 kubectl label pod <name> ________。

  2. 给 Pod 加 annotation owner=team-a，命令是 kubectl ________ pod <name> owner=team-a。

  3. kubectl expose pod web-prod -n default 失败，但 kubectl expose pod web-prod -n prod 成功，原因是 Service 的 selector 只能选 ________ 的 Pod。

  4. 列出至少 4 个不受 Namespace 约束的资源：、、、。

  5. Label selector env in (dev, test) 的含义是：env 的值等于 ________ 或 ________。

  6. 把 Pod 的 annotation owner 改成新值，需要加 ________ 参数。

  7. kubectl get pods --all-namespaces -l tier=frontend 这个命令中，--all-namespaces 的作用是 ________。

三、简答题（每题 5 分，共 15 分）​

  1. 用一句话说清 Namespace 和 Label 的区别，再各举一个使用场景。

  2. 你执行 kubectl get pods -l env!=prod，返回了一个没有 env 标签的 Pod，请解释为什么。

  3. Calico CNI 给 Pod 自动注入了 cni.projectcalico.org/podIP 这样的数据，用的是 label 还是 annotation？为什么不用另一种？

四、实操题（共 15 分）​

题目（15 分）​

你的集群里现在有一个 Pod 叫 web（在 default namespace）。请完成以下操作，每步写出完整命令：

  1. （3 分）给 web 打上 label app=web 和 tier=frontend

  2. （3 分）给 web 加上 annotation maintainer=ops-team

  3. （3 分）用一条命令同时筛选出 app=web 的 Pod 并以 YAML 格式输出

  4. （3 分）把 annotation maintainer 的值改成 dev-team

  5. （3 分）删除 web 上的 label tier 和 annotation maintainer（写出两条命令）

参考答案​

点击展开

一、判断题​

  1. × Namespace 不支持嵌套，都是平级的。

  2. × 级联删除会删除 namespace 下的所有资源，包括 ConfigMap、Secret、Service 等。

  3. √ != 和 notin 会命中没有该 label 的 Pod，这是 Day 3 验证过的行为。

  4. × Annotation 不能被 selector 筛选，这正是它和 Label 的核心区别。

  5. √ 集群级资源不在任何 namespace 中，可见性由 RBAC 控制。

二、填空题​

  1. env-
  2. annotate
  3. 同一个 namespace
  4. Node、PV、Namespace、StorageClass、CRD（任选 4 个）
  5. dev、test
  6. --overwrite
  7. 跨所有 namespace 搜索（不限单个 namespace）

三、简答题​

  1. Namespace 是墙（物理隔离，资源互相看不见），用于多租户/多环境隔离，如 dev/prod 各建一个。Label 是贴纸（逻辑分类，不隔离），用于筛选和路由，如 app=web, tier=frontend 让 Service 能选中后端 Pod。

  2. != selector 的语义是"key 的值不等于某值"，对没有该 label 的资源，K8S 判断为"不等于"也成立，所以会命中。同理 notin 和 !key（存在性否定）也有类似行为。这是 Day 3 实验验证过的。

  3. 用的是 annotation。因为 podIP 是元数据信息，不需要被 selector 筛选。如果用 label，会出现在 kubectl get pods --show-labels 里造成干扰。Label 是给人/控制器筛选用的，annotation 是给工具存元数据的。

四、实操题​

# 1.
kubectl label pod web app=web tier=frontend

# 2.
kubectl annotate pod web maintainer=ops-team

# 3.
kubectl get pod -l app=web -o yaml

# 4.
kubectl annotate pod web maintainer=dev-team --overwrite

# 5.
kubectl label pod web tier-
kubectl annotate pod web maintainer-
