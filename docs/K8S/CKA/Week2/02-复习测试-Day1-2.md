## 二、判断题（每题 2 分，共 10 分）

1. □ Pod 的 RESTARTS 计数器在容器被替换（如改 image）时会加 1。

2. □ `kubectl logs <pod> --previous` 在任何情况下都能拿到上一次容器实例的日志。

3. □ emptyDir 的数据在容器崩溃重启后会丢失，只有 Pod 删除时才丢失。

4. □ `kubectl get pod web-v2 -l env=dev` 是合法的命令，会返回名为 web-v2 且有 env=dev label 的 Pod。

5. □ `env!=dev` 这个 selector 会匹配没有 env label 的 Pod。

## 三、简答题（每题 8 分，共 40 分）

1. ImagePullBackOff 和 CrashLoopBackOff 的区别是什么？从失败阶段、describe 中的关键信息、第一个该查的地方三个角度回答。

2. 你在实验中用 jsonpath 提取了多容器 Pod 各容器的状态。写出那条 jsonpath 命令，并解释 `containerStatuses` 是什么结构。

3. `kubectl edit pod` 修改 `command` 字段被拒绝后，正确的修改流程是什么？写出完整步骤。

4. 你在实验中执行 `command: ["nginx"]` 导致 Pod 进入 Completed 状态。解释原因和正确写法。

5. 解释 `create -f` 和 `apply -f` 的区别，以及为什么"删了重建"场景推荐用 `create`。

## 四、实操题（每题 10 分，共 30 分）

### 题 1：创建多容器 Pod 并排障

用 dry-run 生成 YAML，创建一个包含两个容器的 Pod：
- 容器 `writer`：busybox:1.36，每 3 秒往 `/shared/data.txt` 写入当前时间
- 容器 `reader`：busybox:1.36，持续 `tail -f /shared/data.txt`
- 两者通过 emptyDir 共享 `/shared`

创建后用一条命令验证两个容器的 restartCount 和 state。

### 题 2：Pod spec immutable 与重建

创建一个 Pod `app1`（nginx:1.27）。尝试用 `kubectl edit` 给它加 `command: ["sleep", "3600"]`，记录报错。然后用导出→删除→重建的方式创建 `app2`，带上这个 command。验证 command 生效。

### 题 3：Label 与 selector 综合题

创建三个 Pod：
- `pod-a`：labels `env=dev,tier=frontend`
- `pod-b`：labels `env=prod,tier=backend`
- `pod-c`：labels `tier=frontend`（注意：没有 env label）

写出四条 selector 命令，分别返回：
1. 只有 pod-a
2. pod-a 和 pod-c（提示：注意 `!=` 的行为）
3. pod-b
4. pod-a 和 pod-b

## 答案与评分标准

### 一、填空题

1. Pending → ContainerCreating → Running
2. 指数（exponential）；300（5 分钟）
3. 只在本地生成不真正创建 Pod；输出为 YAML 格式
4. image（或其他白名单字段）；activeDeadlineSeconds / tolerations / terminationGracePeriodSeconds（任填两个）
5. 删除该 label（key 后加减号 = 删除操作）
6. 网络（同一 IP/localhost 互通）；存储（volume）；生命周期（各自重启）
7. ENTRYPOINT；CMD

### 二、判断题

1. ❌ 容器替换不计入 RESTARTS（RESTARTS 只统计按 restartPolicy 重新拉起）
2. ❌ 上一个实例的日志文件被 kubelet GC 删掉时会报 `unable to retrieve container logs`
3. ❌ 容器崩溃重启不会丢 emptyDir 数据（volume 在 Pod 层，不是容器层）
4. ❌ pod 名（精确点名）和 selector（批量筛选）互斥，会报 `name cannot be provided when a selector is specified`
5. ✅ `!=` 匹配"key 不存在"和"key 存在但值不等于"两类对象

### 三、简答题（要点）

1. 
   - 失败阶段：ImagePullBackOff 在镜像拉取阶段（容器从未创建）；CrashLoopBackOff 在容器启动后退出（Exit Code ≠ 0）
   - describe 关键信息：ImagePullBackOff 没有 Exit Code（容器没跑过）；CrashLoopBackOff 有 Exit Code 在 Last State
   - 第一个查的地方：ImagePullBackOff → describe 的 Events 段；CrashLoopBackOff → logs --previous + describe 的 Last State

2. 命令：
   ```
   kubectl get pod <name> -o jsonpath='{range .status.containerStatuses[*]}{.name}{"\t"}{.restartCount}{"\t"}{.state}{"\n"}{end}'
   ```
   `containerStatuses` 是 `.status` 下的数组，每个元素对应一个容器，包含 name、restartCount、state、image、ready 等字段。

3. 
   ```bash
   kubectl get pod <name> -o yaml > new.yaml
   vi new.yaml  # 删 uid/resourceVersion/creationTimestamp/managedFields/status/last-applied-configuration
   #            # 改需要的字段 + 改名
   kubectl delete pod <name>
   kubectl create -f new.yaml
   ```

4. nginx 默认 daemonize：fork 出后台 worker 后主进程 exit 0。容器规则：PID 1 退出 = 容器结束，Exit Code 0 → Completed。正确写法：`command: ["nginx", "-g", "daemon off;"]`，让 nginx 在前台常驻。

5. 
   - create：命令式，一次性创建，对象已存在则报 AlreadyExists
   - apply：声明式，持续期望状态，记录 last-applied-configuration，存在时做三方合并更新
   - "删了重建"用 create：① 刚删了 last-applied-configuration，apply 退化为 create ② Pod spec 大部分不可变，apply 的更新能力无用武之地 ③ create 的报错（AlreadyExists）更直接指向问题

### 四、实操题（评分要点）

**题 1：** YAML 正确（volumes/volumeMounts/两个 containers/command 正确）；验证命令使用 jsonpath 或 describe；两个容器状态正确（writer Running, reader Running, restartCount 都为 0）

**题 2：** edit 加 command 报 Forbidden；导出 YAML 删系统字段；改名为 app2；create 成功；jsonpath 验证 command 为 `["sleep","3600"]`

**题 3：**
1. `kubectl get pods -l env=dev,tier=frontend`（精确 AND）
2. `kubectl get pods -l tier=frontend,env!=prod`（env!=prod 匹配 env=dev 和无 env 的）
   或 `kubectl get pods -l tier=frontend,env!=prod` 
   注意：`env!=prod` 会匹配 pod-a（env=dev）和 pod-c（无 env label）
3. `kubectl get pods -l env=prod,tier=backend`（或 `env=prod`）
4. `kubectl get pods -l 'env in (dev,prod)'`（集合）

**评分建议**：85 分以上 Day 1-2 过关，可推进 Day 3。70-85 分重做错题涉及的实验。70 分以下建议重读笔记再考。
