Week 0-1 复习测试

覆盖：week-0 基线准备 / week-1 集群架构与 kubeadm / K8S安装前置操作 / K8S集群初始化 / CKA备考 规则：闭卷（不看笔记不看文档），建议限时 40 分钟；实操题在集群上做 答案在文末，做完再翻

一、填空题（每空 1 分，共 20 分）​

  1. CKA 考试时长 ____ 小时，及格线 ____ 分，含 ____ 次免费重考。

  2. 2026 版考纲五大域中权重最高的两个：____（30%） 和 ____（25%）。

  3. 考试是开卷考，但只允许开 1 个额外标签页，且只能访问三个官方域名：、、____。

  4. kubectl 生成 YAML 骨架的参数组合是 kubectl run xxx --image=xxx ____ -o yaml。

  5. 控制平面中，唯一对外 API 入口是 ____，集群唯一的状态数据库是 ____。

  6. 决定 Pod 调度到哪个节点的组件是 ____（它只做决策不执行），实际按 PodSpec 拉起容器的是 ____。

  7. 控制平面组件以 ____ Pod 形式运行在 ____ 目录下，由 ____ 直接监控该目录拉起，不经过 apiserver。

  8. 你的集群：Pod 网段是 ____，Service 网段是 ____，CNI 插件是 ____。

  9. kubeadm join 需要两个鉴权要素：____ 和 ____。

  10. 查看集群所有证书到期时间的命令：kubeadm ____ ____。

二、判断题（每题 2 分，共 10 分）​

  1. （ ）K8S 要求关闭 swap，Fedora 的 zram swap 用 swapoff -a 就能永久关闭。

  2. （ ）containerd 默认 SystemdCgroup = false，装完必须改成 true 否则 kubelet 起不来。

  3. （ ）给 containerd 配 hosts.toml mirror 指向阿里云，就能完美解决 registry.k8s.io 被墙的问题。

  4. （ ）kubectl get pods -A -o wide 里 calico-node、kube-proxy 显示节点 IP，是因为它们是静态 Pod。

  5. （ ）kubeadm init 完成后不装 CNI，节点状态也会是 Ready，只是 Pod 之间不通。

三、简答题（每题 8 分，共 40 分）​

  1. 控制平面组件为什么必须 hostNetwork: true + 静态 Pod？用"鸡生蛋"的逻辑讲清楚。（提示：kubelet 启动时序）

  2. kubeadm init 完成后，kubectl get pods -A 发现 CoreDNS 一直 Pending，节点 NotReady。写出排查思路和最可能的原因。

  3. 你的集群选了 Calico 而不是 Flannel。写出两者至少 3 个区别（网络模式、性能、策略支持、默认网段任选三个）。

  4. 你集群 Pod 网段是 10.244.0.0/16，每节点按 /24 分配。这个集群最多能有多少节点？如果想支持更多节点，两条路分别是什么？

  5. kubelet 与 apiserver 通信的证书，和控制平面组件自己的证书（/etc/kubernetes/pki/ 下），在"自动续期"上有什么区别？组件证书到期了怎么续？

四、实操题（每题 10 分，共 30 分，在集群上做）​

  1. 不查笔记：查看 apiserver 证书的有效期（两种方法：openssl 和 kubeadm，各写一条）。

  2. 执行 kubectl get pods -n kube-system -o wide，把结果里的 Pod 分成两类（显示节点 IP 的 / 显示 10.244.x.x 的），并各说明一类原因。

  3. 排障模拟：kubelet 日志刷屏 Unable to register mirror pod because node is not registered yet，apiserver 起不来。凭你搭建集群的经验，写出完整的根因链（从第一环到最后一环）和解决方法。

答案与解析

一、填空​

  1. 2 小时 / 66 分 / 1 次
  2. 故障排除（30%）、集群架构、安装和配置（25%）。注意 2026 新版：工作负载降到 15%，存储 10%，服务网络 20%。
  3. kubernetes.io/docs、kubernetes.io/blog、github.com/kubernetes。搜索引擎和 AI 一律不可用。
  4. --dry-run=client（不是 none，老写法已弃用）
  5. kube-apiserver / etcd。排障口诀：apiserver 坏了 = 全部命令报错；etcd 坏了 = apiserver 报错。
  6. kube-scheduler / kubelet
  7. 静态 Pod / /etc/kubernetes/manifests/ / kubelet
  8. 10.244.0.0/16 / 10.96.0.0/12 / Calico（v3.29.1，IPPool 已改为 10.244.0.0/16）
  9. token / discovery-token-ca-cert-hash（让新节点信任集群 CA）
  10. kubeadm certs check-expiration

二、判断​

  1. ✗ — swapoff -a 只关当前，重启复活。zram 是 systemd service 管理的，必须 systemctl mask systemd-zram-setup@zram0.service。
  2. ✓ — K8S 硬性要求（cgroup 驱动一致）。
  3. ✗ — mirror 会追加 ?ns=registry.k8s.io 且不重写路径，阿里云 404。本项目实际用的是 kubeadm --image-repository registry.aliyuncs.com/google_containers。
  4. ✗ — 原因是 hostNetwork: true，和静态 Pod 无关。etcd/apiserver 既是静态 Pod 又是 hostNetwork，但 coredns 是普通 Pod。
  5. ✗ — 没 CNI 节点直接 NotReady，kubelet 上报的 NetworkReady 条件不满足。

三、简答（要点对照）​

  1. 鸡生蛋：kubelet 启动要先拉起 apiserver，但那时 Calico 还没装，Pod 网络不存在——如果 apiserver 依赖 Pod 网络，它永远起不来。所以控制平面必须 hostNetwork（直接用节点网卡，IP 稳定在 192.168.10.12:6443）+ 静态 Pod（kubelet 直接读 manifests 目录拉起，不需要 apiserver 存在）。这同时解释了：pause 拉不到 → 沙箱建不了 → apiserver 起不来 → 整个集群挂。
  2. 排查思路：kubectl get nodes 看是否 NotReady → 是 → CNI 问题。最可能原因：没装 CNI，或 CNI 的 IPPool 网段与 --pod-network-cidr 不一致。验证：kubectl get ippool default-ipv4-ippool -o jsonpath='{.spec.cidr}'。
  3. 三点任意组合：网络模式（Calico BGP 三层路由 / Flannel VXLAN 二层隧道）；性能（Calico 直接路由更高）；NetworkPolicy（Calico 支持 / Flannel 不支持）；默认 Pod 网段（Calico 192.168.0.0/16 / Flannel 10.244.0.0/16）。
  4. 10.244.0.0/16 按 /24 切 = 256 个节点。两条路：① 扩大 Pod 网段（init 时定死，/12 = 4096 节点）；② 减小每节点分配粒度（Calico IPPool 配 /26 或 /28，同样池子节点数翻 4~16 倍；Flannel 固定 /24 做不到）。
  5. kubelet 的客户端证书自动轮换（默认开启，无需干预）；控制平面组件证书不自动续期（服务端证书被广泛信任，轮换需管理员显式操作）。续期：kubeadm certs renew all，然后重启静态 Pod（删掉 manifests 下的 Pod 或 kill 容器，kubelet 自动用新证书重建）。缓解因素：kubeadm upgrade 会顺带续期。

四、实操（参考命令）​

  1. 方法一：openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text -noout | grep -A2 Validity 方法二：kubeadm certs check-expiration（一次看全部）
  2. 节点 IP 类（hostNetwork，共享节点网络栈，直接操作 iptables/路由表或需稳定监听）：calico-node、kube-proxy、etcd、kube-apiserver、kube-controller-manager、kube-scheduler。 Pod IP 类（普通 Pod，CNI 分配 IP）：coredns、calico-kube-controllers。
  3. 根因链：kubelet 建静态 Pod 前先建 sandbox → sandbox 要拉 pause 镜像 → containerd 默认从 registry.k8s.io 拉（被墙）→ pause 拉不到 → 沙箱建不了 → apiserver 起不来 → 不监听 6443 → kubelet 注册不了节点 → 循环刷屏报错（报错是果不是因）。 解决：改 /etc/containerd/config.toml 中 pinned_images.sandbox 指向阿里云 → systemctl restart containerd。注意 containerd 2.x 用新配置名，网上的 1.x 写法不生效。

计分与建议​

  • 85 分以上：Week 0-1 过关，直接推进 Week 2
  • 70~84：错的题回对应笔记重看，重点是错的简答题（简答题 = 排障题的思路原型）
  • 70 以下：建议把《K8S集群初始化》的"易踩坑记录"整节重读一遍再测一次

错题记录建议：把做错的题号和原因记在笔记里，Week 11（模拟考试与弱项补强）时这就是你的个性化题库。
